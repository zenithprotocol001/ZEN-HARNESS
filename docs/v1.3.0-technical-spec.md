# v1.3.0 — Technical Specification (Live LLM Providers)

**Status**: Frozen contract (2026-09-02)
**Supersedes**: v1.2.x mock-only chat surface
**Goal**: Add OpenAI, Anthropic, and OpenRouter as live chat providers behind a single interface, with API key management, retry policy, and a model selector in the UI — without regressing the v1.2.x mock LLM test surface.

## 1. Scope

In:

- `LLMProvider` abstract base + 3 concrete clients (OpenAI, Anthropic, OpenRouter).
- `ModelRegistry` with 6 hardcoded models (per ADR-0006).
- `provider_client_for(model_id)` factory dispatching by `Model.provider`.
- API key storage via the existing `SecretsService` (per ADR-0007).
- 3-attempt retry policy (1 s/2 s linear backoff, 5xx + network only) per ADR-0008.
- `GET /api/models` and `GET /api/models/{id}` on C1.
- `<ModelSelect>` React component in `ChatPanel` header.
- ~60 new tests.

Out (deferred to v1.3.1 or v1.4.0):

- Model config menu (temperature / max_tokens / top_p / system_prompt).
- Conversation branching, attachments, token counter, context-window progress.
- OpenRouter dynamic model discovery (v1.4.0 per ADR-0006).
- Per-secret random nonce in the secrets envelope (deferred; envelope format `0x01` already reserves 16 bytes of headroom per `docs/secrets-model.md`).
- Settings modal for API key entry (Q5 answer: deferred to v1.3.1).

## 2. Frozen contracts

### 2.1 `StreamChunk` (unchanged from v1.2.0)

Defined in `src/dhc/modules/c7_llm_stream_adapter/service.py:45`. Frozen pydantic v2 model:

```python
class StreamChunk(BaseModel):
    model_config = ConfigDict(frozen=True)
    delta: str = Field(default="")
    tool_calls: list[dict] = Field(default_factory=list)
    finish_reason: str | None = None
    raw_index: int = 0
```

**Constraint**: every v1.3.0 provider client **must** yield this exact shape. The chat WS handler, the v1.2.x mock tests, and the 19-check smoke all depend on it. No `done` flag (the WS infers "done" from stream end), no `usage` dict (deferred to v1.3.1 as a non-breaking additive field).

### 2.2 `LLMProvider` abstract base

`src/dhc/integrations/base.py`:

```python
class LLMProvider(ABC):
    provider_name: str  # class attribute; "openai" | "anthropic" | "openrouter"

    @abstractmethod
    async def chat_stream(
        self,
        messages: list[dict],
        model: str,
        api_key: str,
        retry_config: RetryConfig | None = None,
    ) -> AsyncIterator[StreamChunk]:
        """Stream chat completion. `messages` is the OpenAI shape
        ({role, content}). Yields StreamChunk instances; caller infers
        'done' from stream end. Must NOT raise inside the iterator for
        transient failures — the retry loop handles those and only
        raises ProviderError on final failure.
        """
```

### 2.3 `RetryConfig` and `ProviderError`

```python
@dataclass(frozen=True)
class RetryConfig:
    max_attempts: int = 3          # 1 initial + 2 retries
    backoff_seconds: tuple[float, ...] = (1.0, 2.0)  # per ADR-0008 (linear, not exponential)
    retry_on_5xx: bool = True
    retry_on_network_error: bool = True
    retry_on_4xx: bool = False
    connect_timeout_s: float = 5.0
    read_timeout_s: float = 30.0

class ProviderError(RuntimeError):
    """Raised on final (non-retryable) failure. The chat WS handler
    closes the socket with code 1011 when it sees this."""
    def __init__(self, message: str, *, status: int | None = None,
                 provider: str = "", model: str = "") -> None:
        super().__init__(message)
        self.status = status
        self.provider = provider
        self.model = model
```

### 2.4 `Model` and `ModelRegistry`

`src/dhc/services/model_registry.py`:

```python
@dataclass(frozen=True)
class Model:
    id: str            # "openai/gpt-4o-mini"  (provider/model format per ADR-0006)
    name: str          # "GPT-4o mini"
    provider: str      # "openai" | "anthropic" | "openrouter" | "mock"
    context_length: int  # 128000
    pricing_input: float   # USD per 1M tokens
    pricing_output: float  # USD per 1M tokens
    capabilities: frozenset[str]  # {"vision", "tools", "json"}

class ModelRegistry:
    def __init__(self) -> None:
        self._models = self._load_hardcoded_models()

    def list_models(self) -> list[Model]: ...
    def get_model(self, model_id: str) -> Model | None: ...
    def models_for_provider(self, provider: str) -> list[Model]: ...
```

The 6 hardcoded models (frozen):

| id | name | provider | ctx | in $/1M | out $/1M | caps |
|---|---|---|---|---|---|---|
| `mock-llm/default` | Mock LLM (default) | mock | 8192 | 0 | 0 | `{}` |
| `openai/gpt-4o-mini` | GPT-4o mini | openai | 128000 | 0.15 | 0.60 | `{tools, json}` |
| `openai/gpt-4.1` | GPT-4.1 | openai | 1000000 | 2.00 | 8.00 | `{tools, json, vision}` |
| `anthropic/claude-3-5-sonnet-latest` | Claude 3.5 Sonnet | anthropic | 200000 | 3.00 | 15.00 | `{tools, json, vision}` |
| `anthropic/claude-3-5-haiku-latest` | Claude 3.5 Haiku | anthropic | 200000 | 0.80 | 4.00 | `{tools, json}` |
| `openrouter/auto` | OpenRouter Auto | openrouter | 200000 | 0 | 0 | `{tools, json}` |

The `mock-llm/default` entry is **always present** and is what the existing v1.2.x chat surface defaults to. C7's existing `chat_stream(messages, model)` path stays unchanged for this id; the new factory only kicks in for the other 5.

### 2.5 API key naming convention

Per ADR-0007, the convention is:

```
llm_provider_{provider}_{model_id}
```

Where `{model_id}` is the **id without the provider prefix**. Examples:

- `llm_provider_openai_gpt-4o-mini`
- `llm_provider_anthropic_claude-3-5-sonnet-latest`
- `llm_provider_openrouter_auto`

`llm_provider_mock-llm_default` is also stored (value is empty) so the Settings UI can show a single list of configured providers.

The factory `provider_client_for(model)` looks up the API key with `secrets_service.get(f"llm_provider_{provider}_{model_part}")`. If the key is missing AND the model is not the mock, the chat WS handler closes with code `1011` and a payload of `{"error": "missing api key for <model_id>"}`. The UI surfaces this as an inline error in the chat panel with a "Manage keys" link.

### 2.6 `provider_client_for` factory

`src/dhc/integrations/__init__.py`:

```python
def provider_client_for(model: Model) -> LLMProvider:
    """Return a provider client for the given model.

    The mock provider is the C7 mock LLM surface and is NOT a
    subclass of LLMProvider; the caller (C7 dispatch) is responsible
    for short-circuiting on provider == 'mock' before this is called.
    """
    if model.provider == "openai":
        return OpenAIClient()
    if model.provider == "anthropic":
        return AnthropicClient()
    if model.provider == "openrouter":
        return OpenRouterClient()
    raise ProviderError(f"no provider for {model.id}", provider=model.provider)
```

## 3. C7 dispatch (the integration seam)

The existing `LLMStreamAdapter.chat_stream(messages, model)` at `c7_llm_stream_adapter/service.py:85` is **extended** (not replaced) with a new optional `model_registry` and `secrets_service` parameter. The v1.2.x behavior (POST to `base_url/v1/chat/completions` with `Authorization: Bearer {api_key}`) is preserved as the **fallback** when no model registry is provided OR when the model is the mock.

New behavior when `model_registry` and `secrets_service` are set AND `model != "mock-llm/default"`:

1. Look up `Model m = registry.get_model(model)`. If missing → raise `ProviderError`.
2. Look up `api_key = secrets_service.get(f"llm_provider_{m.provider}_{m.id.partition('/')[2]}")`. If missing → raise `ProviderError` with `status=401`.
3. `client = provider_client_for(m)`.
4. `async for chunk in client.chat_stream(messages, m.id, api_key, retry_config=RetryConfig()): yield chunk`.

The C7 wrapper **does not** know about retry math, error formatting, or per-provider request shape. The provider client owns all of that. The wrapper owns the "translate model id → client + key" plumbing.

## 4. HTTP surface additions

```
GET  /api/models            → 200 [{id, name, provider, context_length, pricing_input, pricing_output, capabilities:[]}, ...]
GET  /api/models/{id}       → 200 {Model dict} | 404 {error: "not found"}
```

C1 also gets a new internal helper `resolve_provider_and_key(model_id) -> (Model, str)` used by the WS chat handler. It returns `(Model, api_key)` or raises `ProviderError` with the right context.

## 5. React surface additions

`<ModelSelect>` lives at `apps/web/src/components/ModelSelect.tsx`:

- Fetches `GET /api/models` on mount, caches in component state.
- Renders a `<select>` with grouped `<optgroup>` per provider.
- On change, calls `onChange(model_id)`.
- ChatPanel persists the selection via `PATCH /api/sessions/{id}` with `{"model": model_id}` (the field already exists in `Session` from v1.2.0).
- The currently-selected model id is read from the session object passed in props.

`<ModelSelect>` has no API key entry UI in v1.3.0 (per the deferred-Q5 decision). The user must `curl` the key in. A "Missing API key" banner appears in `ChatPanel` if the chat WS closes with the missing-key error.

## 6. Threat model additions (live providers)

| Adversary | Mitigation |
|---|---|
| A user pastes their OpenAI key into the wrong field | SecretsService encrypts at rest; `GET /api/secrets` returns names only. |
| A network observer between user and OpenAI | The C1 server is loopback-only. The provider client makes outbound HTTPS from the user's machine to OpenAI/Anthropic/OpenRouter; standard TLS protects the wire. The API key never leaves the local machine. |
| A local process reads `~/.dhc/secrets/secrets.log` | Same as v1.2.x: HMAC-SHA256 encrypt-then-MAC envelope. Reading the log without `secrets.key` is opaque. |
| A user accidentally commits the secrets file to git | The `package_relay.ps1` exclude list already drops `~/.dhc/secrets/`. The repo's `.gitignore` should also drop it (verify in v1.3.0 cleanup). |

## 7. Out of scope / explicit non-goals

- No new `StreamChunk` fields (`usage`, `done`). v1.3.1 may add `usage` non-breakingly.
- No model config menu (temperature, max_tokens, etc.). The provider client hardcodes `temperature=0.7, max_tokens=4096` defaults.
- No streaming cancellation from the UI side. The chat handler reads the entire stream before closing the WS frame.
- No provider-side telemetry (token counts, latency histograms) beyond what C10 ObservabilitySink already scrapes.
- No multi-key rotation per provider. One key per `(provider, model_id)`.

## 8. Backward compatibility

- All v1.2.x tests must pass without modification.
- The mock LLM at `tests/fixtures/mock_llm.py` continues to be the default test surface; the live provider clients are only exercised in their own test files using mock aiohttp responses.
- The `dhc-c7` module's public surface (`LLMStreamAdapter`, `StreamChunk`, `BufferOverflow`) is unchanged. The new `model_registry` and `secrets_service` constructor parameters default to `None` and preserve the v1.2.x behavior when unset.
- `serve_c1.py` continues to default to `--llm-base-url` pointing at the mock; v1.3.0 adds no new required CLI flags. The `ModelRegistry` is constructed unconditionally and the dispatch only kicks in when both `model_registry` and `secrets_service` are set on the C7 adapter (they are, by `serve_c1.py`).
